从一个 URL 出发，理解一次 HTTP 请求

浏览器打开网页时发生了什么？沿着地址、连接、请求与响应，把基础概念连起来。

  • #HTTP
  • #Web

请求从哪里开始

在浏览器输入一个 HTTPS 地址后，浏览器需要找到服务器、建立安全连接，再发送 HTTP 请求。实际过程可能复用 DNS 缓存或已有连接，因此每次打开页面的细节并不完全相同。

可以先把它理解为：

  1. 解析地址：区分协议、域名、端口与路径。
  2. 找到服务器：通过 DNS 等机制获得目标地址。
  3. 建立连接：HTTPS 还需要安全握手；HTTP/3 使用 QUIC。
  4. 交换消息：发送请求，接收状态、响应头与响应体。
  5. 呈现页面：解析 HTML，并按需获取 CSS、图片等资源。

请求与响应长什么样

以下用 HTTP/1.1 的文本形式帮助理解：

GET /notes/ HTTP/1.1
Host: example.com
Accept: text/html

服务器可能返回：

HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8

<!doctype html>

200 表示这次请求成功。404 表示没有找到请求的资源；它并不意味着整台服务器不可用。

带着问题观察

打开浏览器的 Network 面板，刷新一个网页，比较不同资源的状态码、响应类型与耗时。

把抽象概念对应到一条真实请求，理解会更牢固。
