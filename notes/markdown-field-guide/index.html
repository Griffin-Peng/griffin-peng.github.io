先写清楚，再写漂亮

笔记首先是写给未来的自己看的。一篇有用的笔记，应当能够回答三个问题：这是什么、为什么需要它、什么时候可以用它。

Markdown 的好处，是让我们用普通文本表达结构，把注意力留给内容。

一份够用的语法清单

想表达的内容 写法
小标题 ## 一个主题
强调 **关键结论**
无序列表 - 一个要点
行内代码 用反引号包住代码
引用 > 一段引用

不必在每篇笔记里使用所有语法。先让结构服务于你要表达的内容。

把例子留在结论旁边

比起只有一句“数组可以映射”，保留一个能够重新运行的小例子通常更有帮助：

const questions = ['是什么', '为什么', '怎么用'];
const outline = questions.map((question) => `- ${question}`);
console.log(outline.join('\n'));

好的笔记不只是保存答案，也保存找到答案的路径。

写完之后的检查

  • 标题是否具体？
  • 有没有一个自己的例子？
  • 是否标明了仍然不确定的部分？
  • 下一次遇到类似问题，能否快速找到这篇笔记？
